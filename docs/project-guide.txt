                                              Abstract

         ABOX2TBOX is an experimental Python pipeline that turns patterns in RDF instance
     assertions into proposed OWL schema axioms. It combines RDFLib, in-memory SQL,
     statistical candidate mining, optional structured model decisions, graph repair, and HermiT
     reasoning. Its output is a candidate ontology for assessment, not an automatically established
     account of a domain.
        This guide explains what the project does, why its components exist, how the notebook
     runs, where its implementation lives, and when another approach is a better fit. It documents
     the current single-model design and the limits of its validation and evaluation. Comparisons
     are engineering judgments grounded in tool capabilities; they are not claims of measured
     superiority.

The central distinction. RDFLib manages RDF; the project builds an induction workflow on
top of it. A model may help judge a candidate. A reasoner checks the consequences of accepted
axioms. These are separate responsibilities.
Reading routes. For the idea, read Sections 1–2. For execution, start at Section 6. For choosing
an approach, read Sections 10 and 11. For research claims, read Sections 9 and 12 first.

1     Purpose and scope

1.1   The problem the project addresses

An RDF dataset may identify people, sensors, transactions, crops, or other entities, yet provide
only fragments of their conceptual structure. There may be no useful class hierarchy, many
entities may be untyped, and relationships may lack an explicit domain or range. Writing the
missing schema by hand can require considerable inspection.
The project proposes a first draft from recurring evidence. Shared property signatures suggest
groups of entities; repeated type co-membership suggests possible subclass relations; repeated
paths suggest role rules. An optional model judges whether some patterns have a plausible
universal interpretation. The resulting OWL graph can then support expert discussion and
further testing.
Useful settings include exploratory ontology construction, comparing multiple schemas inferred
from the same data, and inspecting which regularities a domain expert might formalize. The
project is less appropriate when the schema is already authoritative, when only data-format
validation is needed, or when a production service requires a measured latency and memory
envelope.


1.2   ABox, TBox, and a running example

An ABox contains assertions about individuals. A TBox describes classes and relationships
between classes. OWL gives such statements a logical interpretation and supports deriving
consequences [1].
For example, these instance facts could appear in a Turtle input:
@prefix ex: <https://example.org/> .
ex:alice a ex:GraduateStudent, ex:Student ;
         ex:enrolledAt ex:university1 .
ex:bob   a ex:GraduateStudent, ex:Student ;
         ex:enrolledAt ex:university1 .


A candidate schema statement is:

@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
ex:GraduateStudent rdfs:subClassOf ex:Student .


The two observations motivate a question; they do not establish a universal rule. This tiny
illustration is also below the current offline minimum support of five. The notebook does not
admit it merely because the example looks reasonable.


1.3   The semantic trap: absence is not a negative label

OWL uses an open-world interpretation: an unrecorded fact need not be false. Distinct identifiers
also need not denote distinct individuals [1]. Consequently, a lack of shared observed members
does not prove disjointness. An observed single value per subject does not establish that the
property can never have two values. A functional property can also imply equality of fillers
rather than produce a database-style duplicate-value error.
The pipeline therefore separates observed support, model judgment, and logical validation. Even
after all three, expert assessment and independent evaluation remain necessary before promoting

accessed through Owlready2’s reasoning integration and requires Java [4]. None of these libraries
independently supplies the whole induction method.

4      How the pipeline works

4.1    Parse, filter, and construct the training graph

The notebook parses Turtle using RDFLib. If blank nodes occur, it canonicalizes the graph to
stabilize their identifiers. It removes subjects declared as schema or metadata entities, declared
annotation properties, and predicates in the RDF/RDFS/OWL/XSD metadata namespaces,
with a special allowance for retained domain rdf:type assertions.
This preprocessing defines the induction view. Validation later uses that retained view, not the
entire raw input. For example, filtering can remove owl:sameAs and existing schema assertions.
A successful check therefore must not be described as validation against every statement in the

                                                6
ABOX2TBOX                                                                             Project guide


source file. A dataset containing important existing semantics needs an explicit preservation or
import policy before the workflow is used as an integration system.


4.2   Deterministic hold-outs

With seed 42, the notebook samples 20% of entities that have at least two retained types and
removes one randomly chosen type from each sampled entity. Separately, it removes 15% of
retained non-literal role triples. Counts are rounded; small datasets can have zero hold-outs.
Literal assertions are not withheld by this procedure.
Sorting and canonicalization make the split reproducible for unchanged data and code. The
retained graph becomes training_graph; the original graph is removed from later mining state.
Held-out assertions remain available for recovery evaluation, not for candidate selection or repair.
Type recall is consequently conditional on the multi-typed population. It does not estimate
performance on every entity, on wholly unseen individuals, or on classes absent from training.
Every normal run exports a schema learned from the training subset. There is currently no
separate automatic full-data retraining pass after evaluation.


4.3   Indexed projection and entity grouping

Training triples are inserted into an in-memory SQLite table with subject, predicate, object,
literal status, and datatype columns. Literals use N3 strings, retaining datatype and language
identity for counting. Composite indexes support subject/predicate and predicate/object access.
Untyped subjects are grouped by outgoing and incoming predicate signatures. Micro-clusters
with compatible incoming signatures can merge when their outgoing weighted Jaccard similarity
reaches 0.65. Predicate weights are based on

                                     N                            p∈A∩B w(p)

                    w(p) = log 1 +        ,          Jw (A, B) = P             .

Here N is the retained subject count and df (p) counts subjects using p. A merged core predicate
occurs in at least half of the merged entities.
These clusters are provisional structural groupings. Similar records can reflect a shared ingestion
template rather than a natural kind. Object-only resources with no outgoing subject occurrence
are not automatically handled as a complete entity population by this grouping stage.


4.4   Names and class candidates

The dominant namespace is estimated from retained classes, predicates, and subjects after
standard vocabulary filtering. New class names are formed deterministically from property-name
tokens. A model may choose among those names. Alignment to an existing class requires a close
lexical match, matching observed predicates, and explicit model confirmation.
The generated class descriptions identify a provisional signature grouping. The competency-style
question is a template derived from the signature; it is not independently elicited from domain
stakeholders. Namespace frequency can favor a broad vocabulary over the intended application
namespace, so inspect all newly minted identifiers.

4.5   Taxonomic candidate mining

For observed class instance sets IC and ID , the notebook computes

                                      |IC ∩ ID |                     |IC ∩ ID |
                         sb(C, D) =              ,       J(C, D) =              .
                                         |IC |                       |IC ∪ ID |

The first is observed coverage of C by D, not an independently calibrated probability that C ⊑ D.
A Wilson lower bound summarizes uncertainty in sample coverage; the configured z is 1.28.
Candidate collection uses a maximum directional coverage of at least 0.15 or Jaccard of at least
0.35.
For some non-overlapping pairs involving induced classes, predicate-intent containment provides
another candidate route. If SC and SD are property signatures, the structural evidence toward
C ⊑ D uses |SC ∩ SD |/|SD |: a more specialized description should cover its proposed parent’s
predicates. Such evidence proposes a question; it does not prove that property occurrence defines
class membership. The implementation does not build a complete formal-concept lattice.
Candidates are sorted by observed overlap and identifiers, then capped by MAX_DECISION_PAIRS.
The pairwise mining loops run before this cap, so the cap does not bound the cost of discovering
candidates.


4.6   Role rules and class restrictions

The notebook considers selected role-rule templates:

                            p(x, y) ⇒ q(x, y)                     (subproperty),
                            p(x, y) ⇒ q(y, x)                     (inverse candidate),
                p1 (x, z) ∧ p2 (z, y) ⇒ p3 (x, y)                 (two-hop chain).

It uses support, head coverage, and partial-completeness-style confidence. This is a limited
template miner inspired by the same general concern about incomplete observations that motivates
AMIE; it does not invoke the AMIE implementation [5]. Minimum supporting counts and
additional confidence thresholds apply before a proposal reaches model confirmation.
For local restrictions, positive instances are the observed members of a class and the remaining
observed domain instances act as a comparison population. This population is an operational
negative set, not a guarantee of semantic non-membership. Coverage scores can therefore be
affected by missing types. The one-step heuristic is

                    ϕ = qref + λ(qref − qparent ) − βℓ,     qparent = 0.5,     ℓ = 3,

with qref computed from observed F1, λ = 0.20, and β = 0.03. Existential candidates require
score at least 0.70 and positive coverage at least 0.50. Universal candidates use observed filler
purity at least 0.95 and at least three matching edges. This is not a complete CELOE search.
Mixed literal/object use of a single predicate causes an explicit error, because the exporter cannot
simply declare that predicate as both an OWL object and datatype property. Normalize the
data or define an explicit mapping policy.


4.7   Adjudication and abstention

Taxonomic model decisions choose one of two subclass directions, equivalence, or insufficient
evidence. Admission requires a valid four-choice probability distribution, chosen probability

                                                     8
ABOX2TBOX                                                                              Project guide


at least 0.70, confidence at least 0.55, and necessity score at least 2.5 out of 3. These are
model-reported values.
If no answer is available, offline subclass admission requires exact observed inclusion, support of
at least five, Wilson lower bound at least 0.70, and a strictly smaller observed child class. The
result is marked empirical_inclusion. Equal observed extensions do not become equivalence.
Signature-only candidates do not become offline subclass axioms.
Disjointness, role characteristics, subproperties, inverses, chains, local restrictions, and do-
main/range axioms require explicit confirmation: validity at least 0.90 and necessity at least 2.5.
Property characteristics also require support and the corresponding observed evidence gate. A
lack of observed compositions yields zero transitivity evidence rather than automatic acceptance.
The model is still a fallible judge of universality.


4.8   Repair and complete-export validation

The taxonomy is a directed graph with edges from subclass to superclass. Greedy repair removes
a weak edge from a detected cycle until the graph is acyclic. Transitive reduction removes
redundant asserted edges while preserving reachable named-class relationships. This procedure
is not weighted MaxSAT and makes no global optimality claim.
Equivalences participate in the closure used to detect disjointness conflicts. Role repair propagates
non-simplicity through property relationships and rejects chains that violate its conservative
dependency-order test. Some legal recursive chains may be rejected. OWL 2 DL imposes global
restrictions beyond ordinary RDF syntax, including restrictions on the use of non-simple roles [2].
The custom checks are not a comprehensive external OWL profile validator.
After every accepted axiom has been added, the complete Turtle serialization is parsed back
and checked by HermiT. First, named classes must be satisfiable in the TBox; then the TBox is
checked with retained training assertions and induced memberships. Missing Java, reasoning
errors, inconsistency, and detected unsatisfiable classes stop the export. The reasoner does not
establish empirical truth or whether an induced concept is useful.
Only after validation does the notebook atomically replace the TBox file. The schema remains
a logical hypothesis even after this gate: empirical inclusion can be universally false without
causing a contradiction in the available data.


5     Decision AI and Generative AI

The current code has one active model setting, MODEL_DECISION, whose default value is
clef-flash:latest. It uses that model to select names and judge proposed axioms. There is
no active MODEL_GENERATIVE setting and no separate Qwen text-generation stage.

The terms Decision AI and Generative AI describe roles in this architecture, not necessarily
disjoint kinds of underlying models. The chat fallback generates JSON text to perform a decision
task. That does not create a separate free-form ontology-generation phase.


5.1    The two transport routes

The transport first probes the configured server’s /v1/systemone route, expecting an answers
object. This is a project-specific contract; a standard Ollama installation should not be assumed
to implement it.
If the probe fails, the transport tries /api/chat with JSON output, streaming disabled, temper-
ature zero, and seed 42. Ollama documents this chat endpoint and structured-output options [6].
Both routes use the same configured decision model. If neither succeeds, the run uses statistical
mode. A successful connection is not proof that every later candidate receives a usable decision.


5.2    Would a two-model design be better?

A generator could offer names and definitions beyond the current deterministic vocabulary. It
could also introduce unsupported ideas or steer the judge toward its own wording. A separate
judge does not guarantee independent errors. An engineering decision to add generation should
therefore be based on an ablation study with reviewed axioms, runtime, and cost, rather than
the number of AI stages. Section 11.1 gives a comparison plan.

Restart the kernel and run all cells in order. The default working directory controls relative
paths and discovery of pipeline_support.py. The notebook’s dependency cell is a commented

Offline mode can finish with few expressive axioms and low recall. That is an observable property
of the conservative rules, not evidence that an AI endpoint was silently used. The schema export
contains class declarations and accepted hypotheses; it is not a new copy of the full input ABox.

changes can alter results even when the Python seed is unchanged.

7.1   Budget semantics and audit interpretation

Preflight sizing uses serialized UTF-8 bytes plus a reserve of 128, recorded as estimated_in
put_tokens. This name is historical: it is an estimate, not an exact tokenizer measurement.
Server prompt framing and tokenization can differ. Oversized requests abstain before sending; a
reported input-token overrun disables further calls after the overrun is observed.
Audit records include stage, endpoint, model, timestamp, status, estimated size, and reported
input usage if supplied. Reported usage is None when unknown. No fictitious readiness call is
recorded in offline mode. Shared attempt budgets are consumed in pipeline order, including
naming; later stages may receive no model budget. Some limit-based returns happen before an
audit event is created, so the audit is a request log, not a full ledger of every rejected candidate.


8     Artifacts, provenance, and guarantees

The principal deliverable is a Turtle ontology. It can contain named classes, subclass and
equivalence axioms, disjointness, property declarations and characteristics, domains and object
ranges, local restrictions, subproperties, inverses, and property chains. Which families occur
depends on the data and adjudication outcome.
For subclass axioms, OWL axiom annotations distinguish empirical support from model decision
probability and record confidence, support count, mining mode, and source. Pipeline attribution
uses an IRI for the pipeline agent. PROV-O provides a standard vocabulary for provenance
relationships [7]. The current metadata does not preserve a complete reproducible model
execution: there is no automatically persisted manifest of dataset hashes, model digests, prompts,
responses, every rejection, and all configuration values. Expressive axiom families do not all
carry the same detailed per-axiom source annotations.

What a successful export supports                  What it does not establish

The role metric uses the same construction with held-out named edges. If a hold-out set is empty,
the corresponding result is unavailable. Precision and F1 are None because the dataset does not
supply independently labeled negative assertions. Counting every unobserved fact as false would
contradict the intended incomplete-data setting.
Recovery applies a supported rule fragment: named-class subclass/equivalence closure, do-
mains/ranges, subproperties, inverses, chains, symmetry, reflexivity, and transitivity. It does not
perform full OWL entailment, equality reasoning, existential witness recovery, or restriction-based
type inference. Recall therefore measures the behavior of that fragment, not all inferences HermiT
could potentially support.

and account for indirect subclass entailment. A negative label means the proposed universal
axiom is rejected under the evaluation protocol; it does not require that the two classes be
disjoint.

calibration count is also a coverage indicator, not the size of the entire gold set. Directed subclass
probability combines the chosen direction with equivalence probability mass. Offline overlap

9.3    Descriptive metrics are not accuracy

The following definitions describe the current code rather than a claim of universal metric
standardization. Let C be the number of named classes, P the number of retained domain
properties, and E the reduced named-subclass edge count:

                  P                 E                #{classes with observed members}
         RR =        ,       IR =     ,    CCR =                                      .
                P +E                C                                C
Relationship richness does not measure whether those relationships are correct. Inheritance
richness can exceed 1 in a multiply inherited hierarchy. Coverage is often 1 because the class
universe is itself built from observed memberships. Lexical similarity is a SequenceMatcher-based
heuristic with a common-prefix bonus; it is not an exact Jaro–Winkler implementation.
The axiom expressivity index is the fraction of counted axioms belonging to selected expressive
families. More expressivity can mean more incorrect commitments. Disjointness density counts
admitted disjoint pairs relative to possible named-class pairs; a higher value is not automatically
desirable.

10.2    How these tools relate to this project

Protégé supplies an ontology-editing environment [8]; it is a useful place for a human to inspect
and revise the exported TBox. AMIE mines graph rules [5]; replacing the notebook’s limited
templates with its output would still require mapping supported rules to legal OWL axioms
and validating the resulting ontology. DL-Learner targets supervised learning in OWL and
description logics [9]; it is an alternative to the current heuristic class-expression scoring, not a
drop-in replacement for every pipeline stage.
SHACL specifies RDF graph validation against shapes [10]. A shape that requires an observed
property answers a different question from an OWL axiom whose existential consequence need
not already be materialized in the data. Both can be useful in the same project, provided their
purposes are kept clear.
Jena TDB2 provides persistent RDF storage and querying infrastructure [11]. Its relevance
here is the current memory-heavy data plane. Migrating to it would require redesigning access
and batching; it would not by itself solve candidate quality. OWL 2 EL, QL, and RL define
different expressive restrictions with associated reasoning aims [12]; choosing one is a modeling
and workload decision rather than an automatic quality improvement.


10.3    What would be worse for the current goal?

For a defensible candidate-ontology workflow, unvalidated direct LLM output, non-overlap
treated as proof of disjointness, and calibration against the pipeline’s own selected edges are
weaker designs. They lack an independent basis for the claims being made. An overcomplicated
two-model system can also be a worse choice than a transparent rule baseline if it adds cost
without measured semantic benefit.
Conversely, the current notebook is a worse fit than SHACL for a straightforward “does every
record contain this field?” task, and a worse fit than a persistent store for a workload whose core
requirement is large transactional querying. Those judgments follow from the task definitions,
not from a measured speed ranking.

11     Recommended use and a fair improvement experiment

Start with a deterministic baseline, keep RDFLib as the graph foundation, and use model-assisted
decisions as an experimental addition. Review the proposed ontology before treating it as an
application contract. If the actual need is data-quality enforcement, add explicit shapes rather
than expecting induced OWL axioms to behave like database constraints.


11.1   A comparison that can answer “is AI better?”

Freeze the input version, preprocessing, split seeds, and evaluation protocol. Compare at least
these conditions:

1. A deterministic statistical baseline with the current conservative gates.
2. The same candidate pool with Decision AI adjudication.
3. A generator proposing additional candidates, followed by the same judge and formal validation
   gates. This third condition is a proposed extension.

First evaluate a shared candidate pool to isolate decision quality. Then evaluate end-to-end
discovery separately so a method can receive credit for finding new valid axioms. Do not tune
thresholds on the held-out evaluation set.
Use independently reviewed positive, negative, and uncertain judgments. Report axiom precision
and recall only where the gold protocol defines the candidate universe adequately; keep unsup-
ported or disputed cases visible. Include indirect entailments and equivalence when assessing
taxonomy predictions. Measure named-class coherence, consistency on a preserved evaluation
view, coverage, abstention rate, and rejected-axiom counts alongside semantic quality.
Also report time, peak memory, actual usage where available, route/model version, and expert
review effort. Use repeated splits or independent datasets and provide uncertainty estimates.
The best practical design is the one that improves the required quality target under acceptable
resource and review costs. The current 73-test result does not choose that winner.


12     Known limitations and operational boundaries

1. Finite observations do not prove universal semantics. Statistical subclass hypotheses
   are still emitted as OWL subclass axioms. Their annotations expose their origin; the logic
   itself is not probabilistic.
2. The training view is filtered. Existing schema, annotations, and meta-namespace as-
   sertions can be excluded. Preserve externally required semantics through an explicit future
   policy.
3. Model evidence is narrow. Many requests contain identifiers, counts, or a short proposed
   axiom rather than full domain documentation and representative counterexamples. Model
   necessity scores and probability fields are not independently verified.
4. Memory and mining work are unbounded by request caps. Several RDF graphs,
   a triple-row list, SQLite data, Python sets, candidate lists, and reasoner state can coexist.
   Class pairing is quadratic in the number of classes; selected property-rule searches involve
   property triples. Repeated restriction lookups and large SQL parameter lists are additional
   bottlenecks.
5. The smallest graphs need extra care. At this snapshot, the disjointness-density calcula-
   tion divides by zero when the class count is zero or one. The bundled multi-class tests do not
   establish support for that boundary case. There is no promise that every syntactically valid

ABOX2TBOX                                                                              Project guide


    Turtle file completes the pipeline.
 6. Reproducibility has limits. Fixed seeds stabilize local choices, not arbitrary model-server
    behavior. Greedy repair and finite shared budgets also make ordering part of the method.
 7. The notebook and generator duplicate source. They must be updated together; the
    regression check catches divergence but does not eliminate the maintenance cost. Extraction
    into a single canonical pipeline module would reduce that risk.
 8. Validation stops rather than repairs every contradiction. If an accepted set remains
    incoherent, the final gate fails. There is no complete minimal-conflict explanation or global
    optimization of all axiom families.
 9. Metrics and provenance are partial. Positive-only recall, conditional calibration, and
    in-memory audit data do not constitute a comprehensive benchmark or durable experiment
    record.
10. Full-scale and live-model performance remain unestablished. The documented
    test run covers offline fixtures and mocked transport behavior. It does not establish full
    agricultural-data scalability or live-service quality.


12.1    A sensible development sequence

First address small-input boundaries and make the preprocessing/semantics policy explicit. Next
persist run manifests, all candidate decisions, exact model identifiers, and independent labels.
Then extract a canonical pipeline module and profile parsing, mining, and reasoning separately
on realistic data sizes.
After those foundations, test a dedicated rule learner or class-expression learner where appropriate.
Add a generative proposal stage only as an evaluated extension with explicit provenance, budget
allocation, and independent judging. For large deployments, consider a persistent RDF store
and a deliberately chosen OWL profile. These are proposed next steps, not existing capabilities.

Glossary

  ABox
   Assertions about named or anonymous individuals.
  TBox
   Terminological axioms describing classes and their relationships.
  Candidate axiom
   A statement proposed from evidence, before or after screening; its acceptance does not
   establish domain truth.
  Coherence
   In this guide, the check that named classes intended to be usable are satisfiable; owl:Nothing
   is excluded from the error list.
  Consistency
   The existence of a logical interpretation satisfying the checked ontology and assertions.
  Entailment
   A statement that follows in every interpretation satisfying the premises, under the chosen
   semantics.
  Role / property
   A relationship; an OWL object property relates individuals, and a datatype property relates
   an individual to a literal value.


                                               19
ABOX2TBOX                                                                          Project guide


  Partial completeness
   A rule-scoring assumption about which missing facts can be treated as informative; it is not
   a global guarantee that the graph is complete.
  Calibration
   Agreement between predicted probabilities and empirical label frequencies on a specified,
   independently assessed population.
  Abstention
   A decision to admit no model-backed axiom because evidence, response validity, service
   availability, or budget is insufficient.
